1. Purpose & scope

This FSD specifies how DFS Corporate Portal behaves: actors, roles, screens, APIs, data, workflows, integrations, and non-functional characteristics.

In scope: Web portal, platform admin, partner mobile KYC APIs, franchise flows, portal approvals, DFS/CMS integrations.
Out of scope: Source listing, internal class design, vendor commercial contracts (TBD).

5. End-to-end workflows

5.1 Merchant onboarding → provision

MERCHANT signup → OTP → /onboarding (Entity → Partners → Docs) → Submit (Tracking ID, decision_due_at) → Partner app invites → each App KYC → KYC_COMPLETED → PENDING_APPROVAL → Admin review → Approve → ACTIVE + credentials → DFS corporateonboarding (if enabled) → accountProvisionStatus SUCCESS | FAILED | PENDING

5.2 Sub-merchant

Parent /invites → token → /franchise-onboard → SUB_MERCHANT signup → OTP → onboarding (+ PARENT_AUTH) → KYC → Admin → ACTIVE → provision → Parent confirms commission plan

5.3 Approval workflow

PARTY_ADMIN assigns roles → MAKER creates approval_request → CHECKER → APPROVER (may skip) → RELEASER → APPROVED/REJECTED → Actions stored on approval_actions
